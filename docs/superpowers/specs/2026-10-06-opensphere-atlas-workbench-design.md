# OpenSphere Atlas Workbench UI 重构设计规格

- **日期**：2026-10-06
- **状态**：已完成头脑风暴，等待规格审阅；本文件不授权实现代码
- **产品**：OpenSphere Vue3
- **重构类型**：架构级 UI 重构（信息架构、工作台布局、设计令牌与交互层），不重写 GIS 业务引擎

## 1. 背景与目标

OpenSphere 是一个基于 Vue 3、OpenLayers、Cesium、Pinia 与 Element Plus 的 Web GIS 工作台，已支持：2D/3D 切换、图层管理、空间文件导入、WMS、要素样式、分类渲染、绘制量测、空间查询、时间筛选、实时轨迹、轨迹回放、热力/聚合、坐标转换与本地工作区保存。

当前产品功能边界已足够完整，但 UI 呈现更接近开发期工具组合：顶栏承载过多任务，部分功能位于“更多”菜单，任务面板以可自由拖动的浮窗为主，视觉令牌散落在多个 CSS 文件中。目标不是添加演示型数据大屏，而是让产品呈现为可长期使用、可售卖的**专业 GIS 工作台**。

### 成功定义

1. 地图保持工作中心，专业用户能持续看到空间上下文。
2. 用户能按任务找到功能：内容与数据、编辑、分析、时间、监测，而不需要记忆顶栏或浮窗位置。
3. 选中对象后显示相应设置，避免多个无关面板同时干扰。
4. 现有 GIS 功能和业务逻辑不丢失、不降级。
5. 视觉层次、状态、间距、颜色、圆角、地图控件统一，形成专业商业软件质感。

## 2. 已确认的产品决策

| 决策项 | 已确认结果 |
| --- | --- |
| 主要用户 | 专业 GIS 用户：测绘、规划、自然资源、工程等桌面作业场景 |
| 主 UI 方向 | “融合专业工作台”：ArcGIS 式信息架构 + Mapbox 式地图编辑体验 + 国内 GIS 的数据工作流 |
| 默认入口 | “图层与数据”优先，而非仪表盘、分析或实时监测 |
| 主题 | Graphite Atlas：深石墨工作台、克制蓝强调色、地图优先；第一版不实现完整浅色主题，但结构需支持后续扩展 |
| 桌面策略 | 桌面专业工作流优先；窄屏以收起/抽屉策略降级 |
| 范围 | 先做工作台 UI、交互和设计系统；不重写地图、导入、图层、轨迹、2D/3D 等业务引擎 |

## 3. 研究取向与参考原则

本设计吸收成熟产品的交互模式，不复制其品牌、图形资产或页面外观：

- **ArcGIS Map Viewer**：将内容工具与设置工具分离；图层选中后展示相应设置，建立清晰的内容区和上下文配置区。
  - https://doc.arcgis.com/en/arcgis-online/get-started/get-started-with-mv.htm
- **Mapbox Studio**：地图画布优先，图层与样式配置具有明确编辑上下文，数据、样式和可视化紧密联动。
  - https://www.mapbox.com/mapbox-studio
- **SuperMap iPortal / DataViz**：数据导入、在线制图、时空数据、地图联动和工作台化业务流贴近国内专业 GIS 需求。
  - https://enonline.supermap.com/iPortal9D/iP/What_is_New.htm

应避免的方向：传统 Ribbon 堆叠、常驻大面积仪表盘、为“科技感”而增加的霓虹/发光特效、伪 KPI 和会遮挡地图的数据卡片。

## 4. 产品概念：OpenSphere Atlas Workbench

### 4.1 设计原则

1. **地图优先**：地图为主画布；不操作时，检查器和面板只占必要空间。
2. **任务优先**：以用户目标分组，而不是以技术组件或 API 分组。
3. **上下文优先**：选图层配置图层，选要素查看要素，进入任务显示任务参数。
4. **专业且克制**：高信息密度、低视觉噪声、稳定的交互反馈。
5. **渐进披露**：高级设置可展开；高频能力始终可达。
6. **可迁移**：布局壳层与 GIS 业务逻辑分离，重构能分阶段交付。

### 4.2 工作台总体布局

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 品牌 / 工作区 | 命令搜索、地点、坐标 | 保存状态 · 2D/3D · 底图 · 设置     │
├───────┬──────────────────────┬─────────────────────────────┬───────────────┤
│ 一级  │ 任务内容面板          │ 地图画布                     │ 上下文检查器  │
│ 图标轨│                      │                             │               │
│ 内容  │ 图层树 / 导入 / 图例  │ 浮动地图快捷控件             │ 图层概览      │
│ 数据  │                      │ 缩放、定位、罗盘、底图        │ 样式/字段     │
│ 编辑  │                      │                             │ 筛选/图例     │
│ 分析  │                      │                             │ 要素/任务参数 │
│ 时间  │                      │                             │               │
│ 监测  │                      │                             │               │
├───────┴──────────────────────┴─────────────────────────────┴───────────────┤
│ 可展开底部抽屉：时间轴 / 属性表 / 实时对象 / 轨迹回放       状态与坐标     │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 4.3 区域职责

#### A. Workbench Header（全局顶部栏）

- 左侧：产品标识、当前工作区名称、工作区状态。
- 中部：统一命令搜索，可检索地点、坐标、图层和命令。
- 右侧：保存状态、2D/3D 切换、底图选择、设置/帮助入口。
- 从当前顶栏迁出：图层、绘制、时间轴、空间查询、样式、实时轨迹和回放等任务工具。
- 顶栏高度目标为 48–52px，减少视觉拥挤。

#### B. Primary Rail（一级任务图标轨）

固定在左侧，提供六类任务入口：

| 一级入口 | 包含的现有能力 |
| --- | --- |
| 内容 | 图层树、可见性、排序、图例、底图、WMS |
| 数据 | 本地导入、数据源、属性表、导出 |
| 编辑 | 绘制、量测、要素编辑、基础样式、分类样式 |
| 分析 | 空间查询、范围、筛选、地点搜索、坐标定位、热力/聚合 |
| 时间 | 时间字段、时间范围、时间轴、轨迹回放 |
| 监测 | WebSocket 实时轨迹、连接状态、目标列表、地图跟随 |

选中态使用图标填充、蓝色强调条和明确标签，不只依靠颜色。

#### C. Content Panel（左侧任务内容面板）

- 默认状态：打开“内容 / 图层”。
- 宽度建议 304–344px，可调整、可完全收起。
- 空工作区展示三个主要动作：**导入空间数据**、**添加 WMS/服务**、**新建绘制图层**。
- 图层行至少包含：可见性、类型图标、名称、状态/要素数、更多操作；支持分组与排序。
- 取代当前默认自由拖动的 `ToolDock`。浮动“专注编辑”可作为后续显式能力，不再是常规入口。

#### D. Map Canvas（中央地图画布）

- 复用现有 `MapView.vue`、OpenLayers、Cesium 与 2D/3D 同步逻辑。
- 右侧地图控件收拢为两个纵向组：导航（缩放、定位、罗盘）和视图（底图、2D/3D、全图）。
- 保留现有量测、绘制、要素选中、地图提示和地图状态反馈。
- 画布避免常驻卡片/仪表盘遮挡。

#### E. Inspector Panel（右侧上下文检查器）

只在具备对象或任务上下文时出现；默认隐藏，保持地图宽度。

- 图层检查器：概览、样式、字段、筛选、图例。
- 要素检查器：要素摘要、属性、定位、编辑/删除。
- 任务检查器：当前查询、绘制、样式或分析的参数。
- 宽度建议 336–384px，可调整、可关闭。

#### F. Bottom Drawer（底部抽屉）

统一承载时态和表格型内容，避免多个独立浮窗互相覆盖：

- 时间轴与时间筛选。
- 查询结果属性表。
- 实时目标与连接状态。
- 轨迹回放控制。

支持收起、半高和全高三种状态；地图状态条始终保留缩放、坐标、底图/坐标系等精炼信息。

## 5. 关键工作流

### 5.1 默认进入和空工作区

1. 进入后，左侧默认显示“内容 / 图层”。
2. 若工作区有数据，展示图层树和当前地图范围。
3. 若工作区为空，显示清晰的三动作空状态，禁止只显示泛化占位符。
4. 导入完成后：自动定位到数据范围 → 选中新图层 → 打开右侧概览检查器 → 提示文件数、要素数和坐标识别结果。

### 5.2 图层编辑

1. 用户在图层树选择图层。
2. 地图及图层行提供选择反馈。
3. 右侧检查器切换为图层概览；样式、字段、筛选、图例作为明确标签。
4. 参数变化即时在地图预览，原有样式与分类渲染逻辑复用。

### 5.3 分析和查询

1. 左轨进入“分析”。
2. 左侧任务面板选择范围、条件、地点、坐标或可视化能力。
3. 地图进入临时任务状态，并给予明确的模式提示和退出方式。
4. 结果进入图层组、右侧检查器或底部属性表，依据结果类型展示。

### 5.4 时间与实时轨迹

1. 时间筛选、时间轴、实时轨迹和回放均保留地图为主。
2. 控制器进入底部抽屉，而不是占用独立浮动窗口。
3. 实时连接状态用可读文本、语义色和最后更新时间表达，不能只用闪烁动画。

### 5.5 命令搜索与快捷访问

- 顶部搜索扩展为地点、坐标、图层和命令的统一入口。
- 后续可引入 `Ctrl/Cmd + K` 呼起命令面板。
- 常用快捷键仅在有稳定语义、不会与浏览器/地图原生操作冲突时添加；`Esc` 必须可靠退出临时地图模式或关闭检查器。

## 6. Graphite Atlas 视觉系统

### 6.1 颜色与层级

| 令牌类别 | 目的 |
| --- | --- |
| `--os-bg-canvas` | 地图外壳与极深背景 |
| `--os-bg-shell` | 顶栏、一级导航轨 |
| `--os-bg-surface` | 内容面板、检查器、抽屉 |
| `--os-bg-elevated` | 菜单、弹层、活动控制 |
| `--os-border-subtle/strong` | 面板分层、焦点和分割 |
| `--os-text-primary/secondary/muted` | 信息层级 |
| `--os-accent` | Arc Blue，用于选择、焦点和主要动作 |
| `--os-success/warning/danger` | 连接、风险与破坏性语义 |

规则：深石墨而非纯黑；强调色只服务于状态和行动；地图数据颜色不与系统语义色竞争。

### 6.2 尺寸与排版

- 间距：以 8px 为基本单位，保留 4px 微间距。
- 控件：常规 32px；紧凑地图/工具控件 28px；顶栏 48–52px。
- 圆角：面板和弹层 6–8px；工具按钮 6px；禁止过度胶囊化。
- 字体：`Inter, PingFang SC, Microsoft YaHei, sans-serif`；坐标、标识和数值采用等宽字体栈。
- 建议文本等级：12px 辅助、13px 控件、14px 正文、16px 区域标题、20px 页面级标题。

### 6.3 状态和动效

- 选中：背景微变化 + 3px 强调条/边框 + 清晰文本对比。
- Hover：120–160ms 的颜色/阴影变化，不用大幅位移。
- 面板展开/收起：160–220ms，尊重 `prefers-reduced-motion`。
- 保存、加载、错误状态必须具备文字说明，不能只使用颜色或图标。

### 6.4 设计令牌草案

```css
:root {
  --os-bg-canvas: #0b1018;
  --os-bg-shell: #121923;
  --os-bg-surface: #18212d;
  --os-bg-elevated: #202b38;
  --os-border-subtle: #2a3746;
  --os-border-strong: #41546a;
  --os-text-primary: #f3f7fb;
  --os-text-secondary: #b8c5d3;
  --os-text-muted: #7d91a5;
  --os-accent: #2f80ed;
  --os-success: #35b979;
  --os-warning: #e6a23c;
  --os-danger: #ed6a5e;
  --os-radius-sm: 6px;
  --os-radius-md: 8px;
}
```

色值将在实现阶段通过真实地图底图、Element Plus 对比度和可访问性检查微调，不应被视为不可更改的品牌色。

## 7. 组件与代码映射

目标是用 UI 容器与设计系统隔离布局重构，尽量保留业务面板和 map facade。

| 当前组件/文件 | 目标角色 | 迁移策略 |
| --- | --- | --- |
| `src/views/AppView.vue` | `WorkbenchShell` | 重组为头部、导航轨、左右面板、地图和底部抽屉的布局容器 |
| `src/layout/AppTopbar.vue` | `WorkbenchHeader` | 精简为全局级能力；迁出任务工具 |
| `src/layout/ToolDock.vue` | `ContentPanel` / `InspectorPanel` | 保留活跃工具状态，不以漂浮面板承载默认工作流 |
| `src/components/LayerWorkspacePanel.vue` | `LayersWorkspace` | 保留图层、范围、筛选、地点能力，增强图层树与空状态 |
| 样式/图例/要素面板 | `InspectorPanel` 子面板 | 以选择对象和任务状态挂载 |
| `src/layout/MapStatusBar.vue` | 精简状态栏 | 保留/增强坐标、缩放、底图、坐标系状态 |
| `src/styles.css` | token 基础和 Element Plus 覆盖 | 拆分为设计令牌、工作台布局、地图控件和业务面板样式 |

建议的 UI 容器目录（实施时再创建）：

```text
src/layout/
  WorkbenchShell.vue
  WorkbenchHeader.vue
  PrimaryRail.vue
  ContentPanel.vue
  InspectorPanel.vue
  BottomDrawer.vue
  MapQuickControls.vue
src/styles/
  tokens.css

  element-plus-overrides.css
```

不要求在第一阶段完整移动每个业务面板；先建立壳层和适配层，降低大规模重构风险。

## 8. 响应式、可访问性与质量规则

### 8.1 响应式

| 视口 | 行为 |
| --- | --- |
| 1440px 及以上 | 左内容面板和右检查器可同时显示；地图为主体 |
| 1024–1439px | 右检查器默认可收起；左面板保持可调整宽度 |
| 768–1023px | 一级图标轨保留；内容与检查器使用抽屉；底部抽屉降为弹层 |
| 小于 768px | 维持基础浏览、搜索、图层和定位；复杂制图/分析给出专业桌面体验提示而非做不可用的缩小版 |

### 8.2 可访问性

- 所有可操作控件具备可见焦点、名称和键盘路径。
- 不用颜色作为唯一状态表达方式。
- 文本与表面达到可读对比度；地图覆盖物应考虑各种底图。
- 键盘焦点不被地图 canvas 或抽屉困住；弹层具备正确关闭和焦点返回行为。
- 动效遵从 `prefers-reduced-motion`。

## 9. 迁移阶段与验收

### Phase 1：基础壳层与令牌

- 建立 Graphite Atlas token、统一字体/控件/Element Plus 覆盖。
- 构建新顶栏、一级导航轨、地图快捷控件和精简状态栏。
- 现有功能不减少，构建与测试持续通过。

### Phase 2：图层与数据优先工作流

- 建立左侧内容面板、图层树、导入入口和空状态。
- 建立右侧图层检查器，迁移基础样式、分类样式、筛选、图例和要素信息。
- 删除默认工作路径对“更多菜单 + 浮动窗口”的依赖。

### Phase 3：分析、编辑、时间与监测

- 按任务迁移绘制、量测、查询、地点、坐标、热力/聚合。
- 建立底部抽屉，整合时间轴、属性表、实时轨迹和回放。

### Phase 4：质量与适配

- 完成关键响应式断点、键盘路径、状态/空状态、性能和视觉回归检查。

### 验收清单

1. 现有导入、WMS、图层、样式、绘制、查询、时间、实时轨迹、回放、2D/3D、工作区保存恢复都有明确入口。
2. 1440×900 下常态地图画布不被常驻面板过度挤压；检查器只有在有上下文时出现。
3. 顶栏只承载全局能力；业务任务不集中在“更多”菜单。
4. 选图层、要素和任务的反馈明确、可预测、即时呈现。
5. 新样式不再依赖分散的硬编码颜色/尺寸补丁。
6. `pnpm typecheck`、`pnpm test`、`pnpm build` 均通过；2D/3D 和地图覆盖层无层级回归。

## 10. 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| UI 大改导致地图业务回归 | 保留 `MapView` 与 map facade 接口；壳层先行、业务面板逐块迁移 |
| Element Plus 默认主题与深色工作台冲突 | 通过 token 和集中式变量覆盖，不在各业务组件散布覆盖规则 |
| Cesium / OpenLayers 画布与面板 z-index 冲突 | 先定义工作台层级表，再迁移覆盖层与抽屉 |
| 现有拖动浮窗用户习惯 | 保留可选专注编辑/弹出模式，但默认采用可调整的固定面板 |
| 全部功能一次迁移过大 | 严格按四个阶段交付，每阶段保持可构建、可测试状态 |

## 11. 非目标

- 不开发新的 GIS 分析算法或后端服务。
- 不更换 OpenLayers、Cesium、Pinia 或 Element Plus。
- 不做仪表盘化大屏或填充式假数据展示。
- 第一阶段不交付完整浅色主题、多人协作、云端发布或项目管理模块。
