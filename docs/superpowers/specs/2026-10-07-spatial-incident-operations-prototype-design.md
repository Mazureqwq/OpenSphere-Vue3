# 空间事件处置前端原型设计规格

**状态：** 已完成设计评审，待书面规格评审
**日期：** 2026-10-07
**范围：** P1 数据工作流与 P2 团队工作流的首个“空间事件处置”前端原型

## 1. 目标与定位

本项目首个产品化切片服务于内部团队、私有化部署场景中的空间事件处置。它不是通用制图工具的功能堆叠，而是让一条事件完成以下闭环：

> 导入或新建事件 → 地图研判与影响范围标注 → 分派处置 → 更新进度 → 主管审核 → 复盘。

第一期为纯前端原型，重点验证数据模型、工作流、界面和权限边界。它必须明确展示为本地演示工作区，不得伪装成真实的多用户协作或合规审计系统。

## 2. 已确认的产品决策

| 维度 | 决策 |
| --- | --- |
| 部署定位 | 内部团队 / 私有化部署 |
| 核心业务 | 空间事件处置与运营调度 |
| 初始数据入口 | 文件导入与人工录入 |
| V1 角色 | 管理员、调度员、主管 |
| 原型协作方式 | 同一浏览器中的“演示角色”切换与任务流 |
| 持久化 | IndexedDB 保存业务数据；localStorage 保存轻量偏好 |
| 后端策略 | 本期不建设后端；先定义 REST + WebSocket 契约和可替换 Repository 边界 |
| 不执行的操作 | 不自动 commit、push 或部署 |

## 3. 范围与非目标

### 3.1 本期范围

- 事件的人工新建、CSV/GeoJSON 批量导入、校验、撤销导入和本地持久化；
- 事件状态机、分派、处置记录、审核、退回、关闭和撤销；
- 管理员、调度员、主管三种演示角色的中心化权限判断；
- 事件队列、地图、检查器、时间线的同一实体联动；
- IndexedDB Repository 与未来 HTTP/WebSocket Repository 的统一领域接口；
- 未来服务端 REST 与 WebSocket 资源/事件契约；
- 面向状态机、权限、导入、持久化、地图联动的自动化测试。

### 3.2 明确非目标

- 真实登录、密码、SSO、组织邀请和服务端 RBAC；
- 多浏览器实时同步、并发修改、冲突解决和离线同步；
- 不可篡改的合规审计；
- 二进制附件上传、对象存储和证据媒体管理；
- SLA 自动升级、催办、规则引擎和自定义角色编辑器；
- 通用的跨文件去重、合并和全量数据治理平台。

## 4. 领域模型

### 4.1 事件实体

`Incident` 是业务的主实体，所有工作台联动围绕同一稳定 ID 进行。

```ts
type IncidentStatus =
  | 'unassigned'
  | 'assigned'
  | 'in_progress'
  | 'pending_review'
  | 'closed'
  | 'cancelled';

type Incident = {
  id: string;
  schemaVersion: 1;
  projectId: string;
  code: string;
  title: string;
  categoryId: string;
  severity: 'low' | 'medium' | 'high' | 'critical';
  status: IncidentStatus;
  geometry: GeoJSON.Geometry;
  createdBy: string;
  assignedTo?: string;
  createdAt: string;
  updatedAt: string;
  version: number;
  sourceBatchId?: string;
  description?: string;
};
```

存储和未来 API 传输统一使用 EPSG:4326 GeoJSON；OpenLayers/Cesium 适配器负责各自画布的投影转换与渲染。前端原型只提供一个固定的本地项目 `local-demo`，所有 `projectId` 均指向该项目；未来项目选择器接入后替换其来源，不改变事件实体。

### 4.2 相关实体

- `IncidentTimelineEntry`：创建、导入、分派、状态更新、处置说明、审核、退回、撤销等追加式本地记录；
- `ImportBatch`：来源文件名、格式、字段映射、总数、成功数、失败数、错误摘要、导入时间与可撤销标识；
- `DemoUser`：演示成员及角色，不代表真实身份系统；
- `IncidentCategory`：管理员可维护的类别与默认严重等级；
- `WorkspaceSnapshot`：用于恢复当前事件工作区的筛选、选择与地图视角。

### 4.3 状态机

| 当前状态 | 合法动作 | 结果状态 | 责任角色 |
| --- | --- | --- | --- |
| 待分派 | 分派 | 已分派 | 调度员、管理员 |
| 已分派 | 开始处置 | 处理中 | 调度员、管理员 |
| 处理中 | 提交审核 | 待审核 | 调度员、管理员 |
| 待审核 | 通过审核 | 已关闭 | 主管、管理员 |
| 待审核 | 退回并说明原因 | 处理中 | 主管、管理员 |
| 非终态（未关闭、未撤销） | 撤销并说明原因 | 已撤销 | 调度员、主管、管理员 |

前端原型中，调度员同时代表事件创建和处置更新角色；`assignedTo` 仅用于演示分派对象，不代表真实登录会话。非法流转必须由领域服务拒绝，而不是仅依赖按钮隐藏。

## 5. 角色与权限

权限由 `can(role, action, incident?)` 或等价的中心化策略服务提供。组件不得硬编码“角色名等于管理员”等判断。

| 动作 | 管理员 | 调度员 | 主管 |
| --- | --- | --- | --- |
| 查看事件与地图 | 是 | 是 | 是 |
| 新建 / 导入事件 | 是 | 是 | 否 |
| 分派、改派、开始处置 | 是 | 是 | 否 |
| 更新处置说明、提交审核 | 是 | 是 | 否 |
| 通过审核、退回、关闭 | 是 | 否 | 是 |
| 撤销事件 | 是 | 是 | 是 |
| 管理演示成员、分类与严重等级 | 是 | 否 | 否 |
| 查看完整时间线与导出摘要 | 是 | 是 | 是 |

顶栏提供“演示角色”切换器，并以可见文字提示其为本地演示状态。切换角色不会改变事件数据，只改变可操作能力。

## 6. P1 数据工作流

### 6.1 人工新建

用户在地图点击点位或绘制影响范围，填写标题、分类、严重等级与说明后创建事件。创建后应同时：

1. 写入事件 Repository；
2. 创建时间线记录；
3. 在地图与事件队列中出现；
4. 自动选中并打开事件检查器。

### 6.2 CSV / GeoJSON 导入

导入向导必须提供：

1. 文件格式识别与预览；
2. CSV 字段映射（标题、分类、严重等级、经纬度或几何字段）；
3. 行级校验及错误原因；
4. 导入摘要（总数、成功数、失败数）；
5. 对可撤销 `ImportBatch` 的撤销操作。

最小校验：标题、有效位置或有效几何。分类和严重等级允许使用默认值补齐。无效行不能静默丢弃；部分失败时，合法记录可以导入，但错误摘要必须保留。

批次撤销仅允许其所有成功导入事件仍处于“待分派”状态；若任一事件已分派、处置、审核、关闭或撤销，系统必须阻止批次撤销并说明原因，用户需逐条撤销对应事件。成功撤销时删除该批次生成的未处置事件与其本地时间线，并保留带 `revokedAt` 的批次摘要。

现有通用 GIS 图层导入继续保留；业务事件必须进入 `Incident` 领域模型，而不是仅作为普通图层属性存在。

### 6.3 本地存储

- IndexedDB：事件、时间线、导入批次、演示成员、分类、工作区快照；
- localStorage：当前演示角色、轻量界面偏好；
- 每条持久化记录包含 `schemaVersion`；
- IndexedDB 不可用或数据迁移失败时，界面需给出明确的阻断提示与恢复指引；
- 本期不实现跨浏览器同步，界面必须说明数据仅保存在当前浏览器。

## 7. 工作台体验

保持 Graphite Atlas 的地图优先与 TaskRail 唯一一级导航原则。

### 7.1 布局

- 左侧 TaskRail 增加“事件”入口；
- 内容面板内包含“事件队列”和“导入批次”二级工作区；
- 地图画布根据状态和严重等级展示事件点/影响范围；
- 右侧检查器展示详情、分派、处置、审核或撤销动作；
- 底部抽屉展示事件时间线与复盘记录。

### 7.2 联动规则

- 从事件队列选择事件：定位地图、打开检查器、高亮地图要素；
- 从地图选择事件：同步高亮队列项并显示事件检查器；
- 状态、分派或审核变化：同步更新地图符号、队列、检查器、时间线和筛选计数；
- 角色切换后：不隐藏数据，仅收敛不可执行的操作并说明原因；
- 页面刷新后：恢复 IndexedDB 数据、当前工作区筛选和最近地图视角。

## 8. 未来服务端契约

本期不请求或模拟网络接口，但 Repository 语义必须能映射到以下 REST 资源。所有资源由项目上下文隔离。

### 8.1 REST 资源

| 方法 | 路径 | 语义 |
| --- | --- | --- |
| `GET` | `/api/me` | 用户、组织、角色和能力集 |
| `GET/POST` | `/api/projects` | 项目/工作区列表与创建 |
| `GET/POST` | `/api/incidents` | 事件查询与创建 |
| `PATCH` | `/api/incidents/{id}` | 事件字段更新 |
| `POST` | `/api/incidents/{id}/assignment` | 分派/改派 |
| `POST` | `/api/incidents/{id}/review` | 通过、退回、关闭 |
| `GET` | `/api/incidents/{id}/timeline` | 时间线读取 |
| `GET/POST` | `/api/import-batches` | 导入批次与结果 |
| `GET/POST/PATCH` | `/api/team-members` | 团队成员管理 |
| `GET/POST/PATCH` | `/api/categories` | 事件分类管理 |

请求和响应中使用稳定 ID、ISO 8601 时间、`schemaVersion` 与 `version`。写操作返回最新实体及版本号，为未来乐观锁与冲突提示预留位置。

### 8.2 WebSocket 事件

未来服务端可向项目订阅者推送：

- `incident.created`
- `incident.updated`
- `incident.assignment.changed`
- `incident.reviewed`
- `import.completed`

前端通过 `IncidentRepository` 等接口屏蔽 IndexedDB 和 HTTP/WebSocket 的差异。后端接入时替换适配器，而不重写状态机、权限策略、地图联动或工作台 UI。

## 9. 架构边界

建议的前端模块边界：

- `incidents/domain`：类型、状态机、权限策略、导入校验规则；
- `incidents/application`：创建、导入、分派、更新、审核、撤销等用例服务；
- `incidents/repositories`：Repository 接口、IndexedDB 实现、内存测试实现；
- `incidents/presentation`：Pinia 状态、队列、表单、检查器、时间线与地图适配；
- `incidents/contracts`：未来 REST / WebSocket DTO 及映射；
- 现有地图 facade：只暴露渲染/定位/选择能力，不承担事件状态机。

数据层必须由应用服务维护一致性；Vue 组件不得直接写 IndexedDB。

## 10. 错误与恢复体验

- 导入校验失败：保留文件和行级错误摘要，允许用户修正后重新导入；
- IndexedDB 读取/迁移失败：告知本地数据无法恢复，提供导出诊断与清空本地演示数据的明确操作；
- 非法状态流转：显示操作原因，不产生部分写入；
- 无权限动作：动作禁用或在尝试时给出角色限制说明；
- 空状态：分别指导新建事件、导入文件、切换演示角色；
- 所有本地保存操作提供成功/失败反馈，禁止静默失败。

## 11. 验收标准

### 11.1 业务闭环

- 调度员可在地图创建事件并完成分派、处置、提交审核；
- 主管可通过审核关闭事件，或退回处理中并留下理由；
- 管理员可维护演示成员和事件分类；
- 事件状态、地图符号、队列、检查器和时间线在一次操作后保持同步；
- 刷新页面后，已保存事件、时间线、导入批次和工作区状态可恢复。

### 11.2 数据与权限

- CSV/GeoJSON 导入能预览、校验、部分成功并显示错误摘要；
- 仅当批次内全部事件仍待分派时，导入批次可撤销其成功导入的事件；
- 非法状态流转被拒绝；
- 角色切换立即收敛动作，无法绕过 UI 直接调用应用服务；
- 现有普通 GIS 图层工作流不被破坏。

### 11.3 工程质量

- 领域状态机、权限策略、导入校验和 Repository 通过自动化测试；
- 持久化恢复、事件联动和角色切换具备回归测试；
- `pnpm test`、`pnpm typecheck`、`pnpm build` 通过；
- 不引入同步 Cesium 首屏依赖或破坏已建立的启动性能预算。

## 12. 后续演进

服务端准备就绪后，按以下顺序替换：

1. 引入真实身份与项目上下文，保留当前权限动作名；
2. 以 HTTP Repository 替换 IndexedDB Repository；
3. 接入 WebSocket 事件并处理远端更新；
4. 启用版本冲突提示和乐观锁；
5. 追加对象存储附件、真实审计、团队协作与 SLA 能力。

此顺序保证原型不是一次性演示代码，而是未来私有化团队产品的可演进交互与领域基础。
